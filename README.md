# River-MOM6

Prepare river-runoff forcing for MOM6, starting with the ARC11k Arctic grid.
The aim is to simplify the existing Hill + GloFAS workflow, remove the Hill
step's PyROMS dependency, and validate replacements against legacy outputs.

## Current status

| Step | Purpose | Status |
| --- | --- | --- |
| 1 — Hill | Place regional Gulf of Alaska river discharge on the MOM6 coastal grid | Implemented without PyROMS; exact legacy agreement for the water year ending in 1993 |
| 2 — GloFAS | Prepare GloFAS runoff on the Arctic MOM6 grid | Planned; not implemented in this repository yet |
| 3 — Merge | Combine Hill and GloFAS runoff | Planned; not implemented in this repository yet |

Only Step 1 is currently supported. Grid and method changes should be evaluated
separately from reproducing the original forcing.

## Install

Use a Python 3 environment with NumPy and netCDF4:

```bash
python -m pip install -r requirements.txt
```

The Hill scripts do not require PyROMS, xarray, SciPy, or xESMF.
Run the commands below from the repository root.

### MOM6 grid

Step 1 requires these files:

- `RAW/GRID/ocean_hgrid.nc`: supergrid coordinates and spacing.
- `RAW/GRID/sea_ice_geometry.nc`: tracer-cell `wet` mask.

The current ARC11k tracer grid has 696 rows and 540 columns. Other local grid
files (`ocean_mask.nc`, `ocean_topog.nc`, and `mask_region_nsdic12_v4_final.nc`)
may also be committed under `RAW/GRID/`, but Step 1 does not read them.

### Hill discharge

The user-provided Hill data location is:

[coastal_runoff on Google Cloud Storage](https://console.cloud.google.com/storage/browser/coastal_runoff)

Download the required discharge files into `RAW/HILL/`, retaining their original
filenames. The scripts currently read local inputs; they do not download data
automatically.

For the 1993 benchmark, the required raw input is:

```text
RAW/HILL/goa_dischargex_09011992_08311993.nc
```

The source must contain:

| Variable | Expected layout | Meaning |
| --- | --- | --- |
| `lon`, `lat` | One-dimensional river-point arrays | River coordinates in degrees |
| `q` | `(number of dates, number of river points)` | Discharge in cubic meters per day |
| `year`, `month`, `day` | Matching one-dimensional date arrays | Dates for each discharge record |

The year argument selects the **ending water year**. Thus `1993` selects the
file covering September 1, 1992 through August 31, 1993; it does not select a
January–December calendar year. Actual output dates come from the source arrays.

## Run Step 1

Create the local data directories as needed:

```bash
mkdir -p RAW/HILL RAW/GLOFAS RAW/GRID
mkdir -p outputs/LEGACY/HILL-on-MOM6 outputs/LEGACY/GLOFAS outputs/LEGACY/MERGED
```

Generate the 1993 output:

```bash
python write_hill_runoff.py 1993
```

This writes:

```text
outputs/HILL-on-MOM6/goa_dischargex_09011992_08311993_q_Hill_NGOA.nc
```

The writer also creates `outputs/MAPPING/hill_to_ARC11k_mapping.npz`.
It reuses that cache when the river coordinates, grid, mask, and area still
match. It rebuilds the mapping if those inputs change.

Process several ending years:

```bash
python write_hill_runoff.py 1994 1995 1996
```

For the remaining local archive, Bash or Zsh can expand the year range:

```bash
python write_hill_runoff.py {1994..2025}
```

Existing outputs are not overwritten by default. To regenerate 1993 and force
a fresh mapping:

```bash
python write_hill_runoff.py 1993 --overwrite --rebuild-mapping
```

An explicit input path can be used instead of year selection:

```bash
python write_hill_runoff.py --source RAW/HILL/goa_dischargex_09011992_08311993.nc
```

Use `--root /path/to/River-MOM6` when running elsewhere. `--hgrid`, `--mask`,
`--hill-dir`, `--output-dir`, and `--mapping` override the default paths.
Relative paths are interpreted against `--root`. See `--help` for all options.

## Reproduce the 1993 legacy comparison

Retain the original PyROMS-produced reference at:

```text
outputs/LEGACY/HILL-on-MOM6/goa_dischargex_09011992_08311993_q_Hill_NGOA.nc
```

This is a separately retained benchmark, not an output to create with the new
writer. A fresh clone needs both this reference file and the raw 1993 input
before it can reproduce the comparison. They are not included in Git.

Run:

```bash
python compare_with_legacy.py --report outputs/hill_1993_comparison.json
```

The comparison uses `rtol=0` and `atol=0` by default. A pass requires exact
runoff values, matching nonzero locations, time values, dimensions, and relevant
variable metadata. Missing/nonfinite runoff, runoff on land, or runoff on the
removed boundaries fails the check. Global provenance attributes such as
`Author` and `Created` are reported separately and do not cause failure.

The report includes RMSE, maximum absolute/relative differences, nonzero-cell
counts, first differing values, and daily integrated discharge using the legacy
area calculation. Numerical comparison is performed one day at a time.

### Validated benchmark

The comparison reported on October 6, 2026 passed for the complete water year
ending in 1993:

| Check | Result |
| --- | --- |
| Records | 365 daily records, September 1, 1992–August 31, 1993 |
| Distinct nonzero coastal cells | 480 in both files |
| Differing runoff values | 0 |
| Nonzero-location mismatches | 0 |
| Maximum absolute runoff difference | 0 kg m⁻² s⁻¹ |
| Runoff RMSE | 0 kg m⁻² s⁻¹ |
| Maximum daily integrated discharge difference | 0 m³ s⁻¹ |
| Missing/nonfinite values or nonzero runoff on land/removed boundaries | 0 |
| Time, dimensions, and relevant variable metadata | Matching |
| Global attributes differing | `Author`, `Created` only |

The writer completed in approximately 8.5 seconds on the user's Mac, including
mapping construction. Timing will depend on hardware and file storage.
This validates the specific 1993 input and grid configuration, not every year
or other MOM6 grid. Preserve the successful local JSON report in Git.

To check another ending year against its separately retained legacy output:

```bash
python write_hill_runoff.py 2004
python compare_with_legacy.py --year 2004 --report outputs/hill_2004_comparison.json
```

The 2004 water year includes February 29. This is a suggested additional check;
no 2004 validation result is claimed here.

Comparison exit codes are `0` for pass, `1` for mismatch, and `2` for an input
or usage error. Looser tolerances are available for diagnosis, but the reported
1993 pass used exact equality.

## Legacy calculations preserved

The replacement retains the original calculation order:

1. Extract MOM6 tracer-cell longitude/latitude from supergrid `x` and `y`
   using `[1::2, 1::2]`.
2. Compute cell area from the sums of the two supergrid `dx` and `dy` segments,
   then multiply them. Arithmetic retains the grid variables' native precision.
3. Identify wet cells adjacent to land using all eight neighbors. Preserve
   coastal-cell traversal order and duplicate entries for tie handling.
4. Add 360 degrees to Hill longitudes in their native precision, then promote
   coordinates to double precision for the mapping calculation.
5. Map each river point to a coastal cell using the legacy spherical distance
   expression. Compute this mapping once rather than every day.
6. Divide `q` by 86400 in the decoded source precision, replace missing values
   with zero, then accumulate contributions in double precision in source order.
7. Zero the first grid row and the last grid column.
8. Convert m³ s⁻¹ to kg m⁻² s⁻¹ using `runoff * 1000 / area`.

For the validated inputs, both `q` and the grid-spacing variables are `float32`.
Promoting them before the division or area calculation changes the numerical
result. Preserving their native arithmetic was necessary for exact agreement.

Output `Runoff` is `float64`, with dimensions `(time, j, i)` and fill value
`1.e30`. Legacy `IQ` and `JQ` dimensions are retained. Time is written as
`days since 1900-01-01` with the Gregorian calendar.

The writer reports conservation before boundary removal and discharge removed
by that operation. It writes each NetCDF through a temporary file and only
replaces the destination after successful completion.

The legacy distance expression is intentionally retained for this regression
target; it should not be treated as a general-purpose global distance algorithm.
The original methods can be inspected in the upstream
[PyROMS littoral routine](https://github.com/ESMG/pyroms/blob/python3/pyroms_toolbox/pyroms_toolbox/get_littoral.py)
and [river remapping routine](https://github.com/ESMG/pyroms/blob/python3/pyroms_toolbox/pyroms_toolbox/src/remap_river.f90).
